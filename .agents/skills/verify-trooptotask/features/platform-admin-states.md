# Platform admin: raw controls and screen states

A platform administrator can reach every admin control by keyboard, sees which page, row or panel is current or expanded, keeps entered values after a failed save, and gets a clear loading, empty, error and denied state on every admin page and modal at desktop and phone widths, in light and dark.

## Sub-features

- `shell`: the admin sidebar, its current-page state, the collapsible sidebar and its phone sheet, `Toggle theme`, `Exit Admin` and the role badge; no focusable control without an action.
- `search`: the global `Search platform admin records` command palette with its searching, empty, failed and result states, keyboard selection and a single instance per width.
- `role-visibility`: super-admin, support and billing see only their admitted pages, header actions, quick actions and record actions; inactive and ordinary accounts are denied.
- `dashboard`: metrics, pending alerts, the signup chart with its screen-reader data table (raw `table`, mapped to `Table`), recent activity and quick actions.
- `directories`: Users and Organizations search, filters, row count and paging held in the URL, with empty and failed reads.
- `records`: User and Organization detail, account-support buttons, and the `SuspendModal` and `TransferOwnershipModal` dialogs with focus entry, focus return, busy and failed-save states.
- `access-requests`: Pending and Reviewed tabs, Approve, Reject and setup-link actions, failed review and the read-only `Reload requests`.
- `feedback`: New, Reviewed and Resolved tabs, the card toggle (raw `button`, mapped to `Button`), Status and Admin Notes, failed save and `Reload Feedback`.
- `announcements`: the create form, Activate or Deactivate, the Delete confirmation, failed create and `Reload Announcements`.
- `audit`: Action and Severity filters and paging in the URL, the details disclosure (raw `details`, mapped to `Accordion` or `Collapsible`) and empty and failed reads.
- `screen-states`: loading, empty, error, denied, disabled, 1280x800 light and 390x844 dark for every admin page and modal.

## How to get to it (user POV)

Sign in as a platform administrator and open `/admin`. The sidebar lists Dashboard, then Support (Users, Organizations, Access Requests, Feedback) and System (Audit Log, Announcements) as the role admits. The header holds `Toggle Sidebar`, the global search (below the header under 1024 px), `Toggle theme` and the role badge. Follow `Inspect` on a User row or an Organization name to open its detail. Super-admins see `Suspend User`, `Suspend`/`Unsuspend` and `Transfer Ownership` there.

## Driving it with verify:app

Expected results come from #1605's acceptance and Phase 10 obligations, the [foundation contract](../../../../docs/ui-foundation-provenance.md#canonical-category-mapping), the [component contracts](component-foundation.md) and the retained behavior in the [platform administration](platform-administration.md), [platform support content](platform-support-content.md) and [notifications and feedback](notifications-feedback.md) recipes. Those recipes stay authoritative for data, permission, persistence, stale-response and step-up journeys; this recipe adds the presentation and state checks they do not state and does not repeat their mutations or direct HTTP proof. Record each cell PASS, FAIL, UNAVAILABLE or UNRUN with the actor, width and theme. A defect stays FAIL until the same step passes on a later candidate.

Actors: `platformReviewer` (active super-admin), `platformSupport` (support), `platformBilling` (retained billing role), `platformInactive` (inactive super-admin row) and `orgMember` (ordinary member, no platform row). `$V actor ROLE admin|admin/users|admin/organizations|admin/access-requests|admin/feedback|admin/audit|admin/announcements` signs in through the normal form. Seeds, in this order: `$V seed platform-admin` (temporary Organization, `orgCreator`/`orgInvitee`/`orgMember` memberships, two pending requests and one completed approved request), then `$V seed audit` (105 same-action A events). `$V platform-state` reads the platform seed's rows. Run the announcement Empty cell before any announcement exists; `seed communications` is not needed for this recipe.

Preconditions: owned launch and `doctor` pass; use the index's `WORKER`, `V`, fresh snapshots and evidence directory. Save `component-foundation.md`'s state reader as `reader.js`. Use native `resize_page` (1280x800, 390x844) and the admin header's visible `Toggle theme` for dark; the theme is per browser context, so set it once per actor and read `document.documentElement.dataset.theme`. Start a keyboard step with `focus()` on the control, then press real `Tab`, `Enter`, `Space`, `ArrowDown` and `Escape`. For the focus ring read `getComputedStyle` `outline` and `box-shadow` while the control matches `:focus-visible` after a real key press. The app ring is a Tailwind `ring` box-shadow (`ring-ring/50` 3px on `Button`, `ring-sidebar-ring` 2px in the sidebar); a UA `auto` outline is the default ring, not the app ring. At each capture read `document.documentElement.scrollWidth` against `innerWidth` and the main region's `scrollWidth` against its `clientWidth`. Page-data failure and hold use `$V network arm-fail|arm-hold PAGE admin-dashboard-read|admin-users-read|admin-organizations-read|admin-feedback-read|admin-announcements-read|admin-audit-read|admin-access-read`; arm on another admin page, then follow the visible sidebar link. Focus the link before arming so a hover prefetch does not consume the one-shot fault, and `network restore` after each case.

## Gotchas

- Admin pages load on the server. Page-data controls fail or hold a SvelteKit client navigation only; a full reload is not intercepted. Arm, then use a visible sidebar link.
- `admin-access-read`, `admin-access/*` and `admin-transfer` need `seed platform-admin` first.
- Both search instances render in the DOM at every width (one is CSS-hidden); read the snapshot, not the DOM count alone, for what a user reaches.
- Announcement Delete currently calls `window.confirm`. The key press or click that opens it blocks every verify:app tool call until it times out (about 120 s), and the dialog is then dismissed. To accept, start the press in the background and send `handle_dialog` with `accept`; it queues behind the press and applies to the open dialog.
- `clean-seeds` refuses a remaining seeded suspension; restore any suspension visibly first. Feedback rows have no delete and stay until worker cleanup.
- A failed suspend or transfer marks the dialog uncertain; it closes only through `Reload details` and then `Cancel` or a matching current state.
