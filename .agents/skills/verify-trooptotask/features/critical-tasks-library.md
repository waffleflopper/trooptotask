# Manage the Critical Tasks library

A member with Critical Tasks configuration access maintains the unit's task definitions. Other members may see readiness without gaining library write access, and one Organization's tasks must not appear in another.

## Sub-features

- `task-library`: create and edit a task's code, title, category, MOS applicability, expiration override and order; save and read it again after reload.
- `task-import`: review valid and invalid CSV rows before a create-only or upsert import, then read back the accepted rows and visible errors.
- `task-lifecycle`: archive and restore a task without deleting an existing completion reference; active and archived filters show the correct records.
- `task-settings`: an Organization-scoped Critical Tasks configurator saves the default expiration and warning window without changing unrelated policy values.
- `task-access`: Critical Tasks `configure`, `view` and no-access members have distinct library permissions. Group-scoped configuration and a foreign Organization cannot write Organization A's library.
- `task-failure`: a duplicate code or failed save leaves the existing task intact and permits a corrected retry.
- `workspace-reuse`: moving between the matrix, Task Library, Reports and a task record keeps the loaded workspace; only each page's own load runs.
- `workspace-read`: the readiness matrix, individual task record, reports and Personnel detail readiness card show active tasks and scoped Personnel after their streamed workspaces load; a configure member also receives archived definitions on every Critical Tasks page, and those pages show only active tasks.

## How to get to it (user POV)

Sign in to Organization A and choose `Critical Tasks` in the Organization navigation, then `Task Library`. Use `New Task`, the selected task's `Edit`, `Archive Task` or `Restore Task`, or `Import CSV`. `Critical Tasks Defaults` is below the library and uses the same configure permission.

## Gotchas

- The Critical Tasks workspace requires read access; the library route load and page require configure access. Archived definitions are decided when the workspace loads, so a member newly granted configure sees them after a reload. A hidden button establishes only the UI affordance; request status plus unchanged rows establish denial.
- Library configuration is Organization-scoped. Group-scoped access may still read limited readiness, but it does not grant an Organization catalog write.
- Task archive hides a definition from active workflows and keeps its ID and completion history. Do not delete seeded completion rows to make an archive check pass.
- Organization policies remain guarded by owner/admin authority; Critical Tasks defaults use the dedicated library form and endpoint.
- The UI provides archive and restore but no task deletion. Restart the owned disposable worker to discard uniquely created proof rows; `clean-seeds` cannot remove UI-created tasks.
