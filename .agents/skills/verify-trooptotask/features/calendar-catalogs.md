# Calendar catalogs

An Organization Calendar configurator maintains status and assignment choices; saved availability and assignments retain their references through edits, while confirmed type deletion explains and removes only linked records.

## Sub-features

- `status-types`: add, edit name/colors, reload, keep ID/order and linked leave; confirmed deletion removes linked availability and records an audit/notification effect.
- `assignment-types`: add Person and Group choices, edit name/code/color and exemptions, keep ID/order and saved assignment; archived history remains readable but not an active choice.
- `calendar-lanes`: choose which assignment types appear as lanes under the dates and in what order; every change is one ordered command that refuses a stale list.
- `catalog-delete`: deleting a retiring assignment type removes its linked assignment but preserves unrelated and archived records.
- `catalog-authorization`: view, operate, Group-scoped and foreign-Organization actors cannot configure the three Calendar catalogs.

## How to get to it (user POV)

With Organization-wide Calendar configuration access, choose `Calendar` → `Settings`. Open the `Status Types` or `Assignment Types` tab, then `Add new` or the row's actions. A status row has `Edit <name>` and `Delete <name>` buttons. An assignment type row has a `Show <name> on the calendar` switch and a `More actions for <name>` menu with `Edit` and `Delete`. Assignment types sit in two lists: `On the calendar · N lanes` in lane order with a `Reorder <name>` grip on each row, and `Duty planner only` sorted by name. Add and Edit open a side sheet. A deletion dialog warns about linked schedule entries or assignments. `Closures` is the third catalog and is driven in [Special days](special-days.md).

## Gotchas

- Calendar `configure` alone does not give a Group-scoped member catalog authority; Organization scope is also required. A missing Settings button proves only the affordance.
- The archived assignment type is excluded from active editing but must remain readable where a saved historical assignment references it. Deletion is intentionally destructive only for the selected linked records; retain unrelated history.
- Native `fill` accepts select and color inputs when they appear in the snapshot. If a custom control is unnamed, inspect its visible label and DOM before a narrowly scoped `evaluate_script` value change, then verify the real Save action and persisted readback.
- Direct authenticated SQL catalog policies and foreign-reference constraints are covered by `supabase/tests/calendar_catalog_scope.sql` in a separate disposable database run; the browser endpoint check does not replace it.
- Native `fill` with an empty string leaves the `Filter <section>` list filtered, because the empty value fires no input event and each section keeps its own filter. To clear one, `type_text` a character and press Backspace.
- With two tabs open, run `select_page` with `bringToFront: true` before `take_screenshot`. A screenshot of a background tab has stalled the owned DevTools until `doctor` recovered about three minutes later.
- `clean-seeds` cannot restore edits or deletions of original fixture rows, or remove types created through Settings. If a seeded edit cannot be restored and read back, restart this owned worker before another dependent journey and report the incomplete restoration.
