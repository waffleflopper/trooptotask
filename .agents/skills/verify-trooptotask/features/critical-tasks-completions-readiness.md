# Record Critical Tasks and inspect readiness

A member with Critical Tasks operate access records validation results and uses the matrix, individual record and reports to find readiness gaps. Current and expiring-soon completions count as ready; expired and missing completions do not. MOS applicability excludes unrelated tasks from the denominator.

## Sub-features

- `completion-record`: create or edit a completion's date, method, validator and notes; preserve its ID on edit and require persistence after reload.
- `completion-recovery`: a failed save retains the modal draft and prior data; a corrected retry persists once. An unresolved response cannot be reported as saved.
- `completion-import`: preview valid, invalid and out-of-scope CSV rows, import only selected valid rows, preserve same-Person/task/date identity on upsert and recover from a failed batch.
- `import-lost-reply`: distinguish refused and unconfirmed completion writes from confirmed saved rows without duplicating dated history.
- `readiness`: matrix cells, individual readiness, Personnel detail and reports agree on current, expiring, expired, missing and not-applicable examples.
- `history`: multiple dated completions use the latest applicable record; archived task history retains its record and dates while leaving active readiness.
- `reports-export`: combined Group/rank/MOS/duty-role filters, error/retry and downloaded matrix/report workbooks preserve independently calculated values and scope.
- `completion-access`: dedicated Critical Tasks operate/view/no-access lanes, Alpha-only/empty Group scopes, unassigned Personnel and foreign Organization targets have distinct allowed and denied behavior.
- `scope-switch`: an A response cannot replace B's records, continue its import in B or enable A's completion controls after switching Organizations.
- `screen-states`: matrix height and sticky scrolling, landmarks, a rejected workspace source, the Record Completion and import dialogs (focus, held title, failed save), person detail tables, Reports metrics, chart data tables, the `Histogram MOS` select, and loading, empty, error, denied, narrow and dark states (step 11).

## How to get to it (user POV)

Choose `ICTLs` in Organization navigation (its tooltip and breadcrumb read `Critical Tasks`). The matrix toolbar (`Critical Tasks controls`) is one row at every width: the `A-Z`/`Group` view switch, the search field, `Critical Tasks group filter` (whose all-option reads `All groups`), `Gaps only`, `Export Excel`, `Import Completions`, `Task Library` (configure only) and `Reports`, then the primary `Record Completion`. Record and import need operate access. As the page narrows, controls fold one at a time into `More Critical Tasks controls`, starting with `Export Excel`, and the search field becomes an icon only after every other control has folded; `Record Completion` stays on the row at every width. Open a Person's linked name for their individual task record; use a task's `Log Completion` or `Edit` control there. Choose `Reports` for filters and `Export Excel`; its toolbar (`Critical task report controls`) folds the same way, with the `Group`, `Rank`, `MOS` and `Duty role` filters leaving from the last to the first and `Export Excel` pinned. The individual record (`Personnel critical task controls`) and the task library (`ICT task library controls`) use the same toolbar: `Input Task` and `New Task` are pinned, and their other controls fold into More. An authorized Personnel detail lists the Person's critical tasks on its Readiness tab. A view-only member can inspect results without recording them.

## Gotchas

- An impossible CSV completion date such as `02/30/2026` is flagged during import review. A malformed import row is refused with `400` and saves nothing. See [Invalid input](invalid-input.md).
- Critical Tasks operate is independent of Personnel and Training; configure is required for library/default writes, not completion recording. Group scope remains authoritative on the server and provider.
- The latest completion is selected by completion date, then creation time. Older history must not overwrite a newer readiness result; same-date import upsert differs from creating a new dated record.
- Critical Tasks expiration uses a per-task override or Organization default. Expiring-soon counts as ready, the same rule Training uses for its warning states.
- The denominator is applicable Person/task assignments, not task count or Personnel count; zero-applicable report readiness is 0%, while a MOS/category matrix can use an empty value.
- History includes archived definitions; active matrix/report denominators exclude them. Archived Personnel history is read-only.
- `actor` establishes sign-in and a starting route, not completion of a streamed workspace or a permission verdict. Its `access` output is `not-assessed` unless it captured the explicit settings-page denial; inspect the actual UI and request/provider evidence.
- Browser sign-in shares the normal ten-auth-POSTs-per-fifteen-minutes limiter; combine journeys per actor and respect a natural cooldown. Never disable the limiter for proof.
- A successful UI write or report does not prove denial, RLS, atomic batch behavior, stale-response safety or another feature's math. Keep direct API/provider and existing component/application/SQL checks separately identified.
