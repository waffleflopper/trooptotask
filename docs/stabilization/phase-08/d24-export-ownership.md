## Declared outcome and design

Complete one ownership cutover for execution, lifecycle persistence/history, manifest, payload assembly, workbook and Web UI. Delivery binds every retained section to its source owner. All five central production paths and five old test paths are removed with their consumers. No compatibility API, new product capability, access expansion or migration is planned. Scheduled Maintenance, generic provider infrastructure and the disabled Personnel-only action retain their separate owners.

The data shape is an exhaustive server-only map of 38 literal section keys to deferred saved-row reads, bound once to the admitted Organization and requester. Data Export uses manifest order and the existing global twelve-query batch limit. A source-owner bundle alternative would introduce serial waterfalls or internal fan-out requiring a second scheduler. The map reuses the existing individual source operations and removes the generic foreign-table fallback. Organization's ordinary reader, Notifications' self-owned reader, Feedback's ordinary/platform RLS and Personnel's separate five-table privileged sensitive port keep their current authority.

Personnel owns the four ordinary Group, Personnel, rank catalog and pin reads. Identity owns progress/preferences; Critical Tasks owns tasks/completions; Sign-in Rosters owns raw roster history. Data Export owns its lifecycle read. The other 28 source reads retain their existing owner operations. Both POST routes use one Delivery binding. Export state and presentation move behind Data Export's consumed Web seam; canonical-Organization keyed lifetimes remain in Delivery. Archives and Data Export both consume the relocated neutral Blob helper with identical cleanup semantics. Shared workbook utilities and all source owners' normal/report/retention consumers remain supported.

The throughput checkpoint preserves the existing twelve-read cap and complete provider traversal. It avoids another scheduler, serial source bundles, browser-to-own-API loops or privileged basic Personnel reads. Root owns integration, application proof and publication. One inherited-model worker owns nine source readers/tests in a separate worktree; its source report is not independent live execution or model diversity. Final independent acceptance is still required.
