## Inventory method and limits

Started with `git status --short`, `git branch --show-current`, `git rev-parse HEAD`, `git worktree list`, sanitized origin inspection and `git ls-files`. Repeated checkout commands against the local V2 reference. Tracked-file enumeration is the source inventory; `rg`/`git grep` locate symbols, followed by implementation reads. Ignored config was enumerated with `git ls-files --others --ignored --exclude-standard` and inspected only for variable names, set/empty status, billing flag and loopback classification. No secret value or personnel row was printed. Lifecycle, CI, Vite/Svelte/Vitest, Supabase, Vercel and environment action files were read before safe checks.

Import inspection used installed TypeScript `createSourceFile` / `forEachChild` over all tracked TS/JS and Svelte `<script>` contents; collected import declarations, re-exports and string-literal dynamic imports; resolved `$lib`, `$features`, relative paths, `.js` to `.ts` and directory indexes. Strongly connected components were computed from resolved imports. Counts include tests and type imports. Nonliteral imports, template semantics, package exports, generated route types and actual bundle runtime reachability are not established by this graph. Cycles were individually inspected to distinguish type-only reverse edges from value cycles. This was scratch analysis, not a new repository governance tool.
