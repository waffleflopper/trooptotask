# Domain Docs

Use [CONTEXT.md](../../CONTEXT.md#language) for canonical terms and the distinctions between them. It is the glossary; behavior contracts, implementation rules, decisions, and work status belong with their owners below.

| Task                                                                                       | Read                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account setup, reviewed access, invitations, or membership                                 | [Acquisition path](../launch-acquisition-path.md) and relevant ADRs 0009/0012 in the [ADR index](../architecture/ADR_INDEX.md)                                                                                                                  |
| Roles, presets, capabilities, scope, or authorization                                      | [Authorization contracts](../architecture/AUTHORIZATION_AND_PROVIDER_BOUNDARIES.md) and ADRs 0001/0002 in the [ADR index](../architecture/ADR_INDEX.md)                                                                                         |
| Feature behavior, data preservation, imports/exports, or readiness                         | Applicable [retained contracts](../stabilization/BASELINE.md#retained-contracts), then the feature-owned implementation and behavioral tests; use [feature organization](feature-organization.md) to locate the owner                           |
| Training report/readiness rules, Personnel URLs or files, or Calendar availability imports | Relevant sections of [retained feature rules](../domain/retained-feature-rules.md)                                                                                                                                                              |
| Module boundaries, shared calculations, or provider access                                 | [Architecture reading map](architecture-governance.md) and [module conventions](../architecture/MODULE_CONVENTIONS.md)                                                                                                                          |
| Historical Duty Roster/Advanced Duty terms or other retired behavior                       | [Stabilization decisions](../architecture/ARCHITECTURE.md#stabilization-decisions), [task status](../stabilization/TODO.md), and the [ADR index](../architecture/ADR_INDEX.md); historical designs do not authorize rebuilding removed features |
| Canonical wording versus compatibility names                                               | ADR 0006 in the [ADR index](../architecture/ADR_INDEX.md)                                                                                                                                                                                       |

Keep glossary entries to short domain definitions and essential distinctions. Place new behavior requirements with the affected feature's contracts, architecture decisions in the relevant architecture document or warranted ADR, and defects or unfinished work in their existing work record.

When a definition is missing or conflicts with behavior, inspect the owning contracts and implementation before changing it. Continue work whose behavior is established; ask only when an unresolved domain decision materially affects the task, following the [operating rules](operating-rules.md).
