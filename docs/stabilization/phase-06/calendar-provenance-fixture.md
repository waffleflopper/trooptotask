# Synthetic Calendar provenance and upgrade contract

Phase 06 D01 [#1328](https://github.com/waffleflopper/trooptotask/issues/1328), leaf 06-01c. This fixture fixes the **pre-retirement** data and access baseline for D02's forward migration and D03's type disposition. It contains synthetic records only. The [loader](06-01c-fixture.sql) commits them so a later migration can run over the same populated database. The [before assertions](06-01c-before.sql) use a rollback-only pgTAP transaction. The [after assertions](06-01c-after.sql) are the independently specified target oracle for D02; D01 cannot claim that they pass before a retirement migration exists.

## Reproduction boundary

Start a **new** disposable, seed-disabled project using the verified input and isolation procedure in the [replay guide](replay-catalog.md). Check that `auth.users` and `public.organizations` are empty after the 137-migration replay and existing SQL suites. Run the loader once with `psql -X -v ON_ERROR_STOP=1` against that project's **exact** database container. Copy `06-01c-before.sql` into only that project's `supabase/tests/` directory and run `supabase test db` for that copied file from the disposable workspace; `npm run db:test` there runs it alongside the original suites. Keep the populated project until its baseline capture is complete, then stop only that project with `supabase stop --workdir <owned-workdir> --project-id <owned-project> --no-backup`. Never use the repository's existing local stack. A future D02 upgrade must use another newly allocated disposable replay and run this fixture and before assertions before applying its forward migration; run the after assertions only afterward. The [execution receipt](../EVIDENCE.md#task-06-01c--synthetic-calendar-provenance-and-access-baseline) records the exact allocation, command outcomes, and cleanup for this D01 run.
