# Organization settings, creation and communications: controls and screen states

An owner or admin governing an Organization can reach every Settings control by keyboard, sees which section is current,
keeps what they typed when a save fails and reads the error beside the field it concerns, and gets a clear loading,
empty, error, denied and disabled state on every section at desktop and phone widths, in light and dark. Creating an
Organization, choosing one on the Dashboard, dismissing an announcement and sending feedback meet the same bar.

## Sub-features

- `settings-shell`: the `Unit settings` section nav and its narrow tabs, the current section, role-derived items,
  streamed badges, each page's display header, the breadcrumb and the `/settings` redirect.
- `general-controls`: the unit name's inline save and Undo, the owner-only last change, the web address with its
  bookmark warning and both confirmations, the Calendar signpost counts, focus return and failed saves that keep the
  entered value with the error on its field.
- `policies-controls`: the loss warning window, training readiness goal and archive retention rows, their live
  sentences, the streamed group readiness, the unsaved state with Undo, validation, busy and failed saves, and the rows
  muted by feature switches.
- `members-controls`: the invite strip, the member filter, the `Manage` access sheet, the row menu's Remove
  confirmation, `Waiting on them` Resend/Revoke and the collapsed invitation history; owner and admin differences.
- `approvals-controls`: the `Pending requests` rows, Approve, Deny with its in-place reason and a failed review.
- `archives-controls`: the `Archived people` table with its search, deletion countdown, Restore, Export and Delete, and
  the `Change retention` link.
- `logs-controls`: the Audit Log scopes, search, day heads, sort and Newer/Older paging; empty, denied and failed
  navigation.
- `exports-controls`: scope chips with streamed counts, the JSON and Excel tiles, per-button progress, the owner's last
  export line, the muted Roster only row, busy and failed export.
- `danger-controls`: Transfer ownership select and confirmation, the streamed destruction counts, the Delete unit
  confirmation, the muted Purge archives now row, failed delete and owner-only access.
- `creation-controls`: `/org/new` form, a server-rejected name, Cancel, and its page styling in both themes.
- `dashboard-picker`: Organization list, pending invitation Accept/Decline, empty state and Toggle theme on
  `/dashboard`.
- `announcement-banner`: the shell announcement Alert and its Dismiss, including a failed dismissal.
- `feedback-modal`: Send Feedback dialog fields, disabled Submit, busy close and failed submit.
- `screen-states`: loading, empty, error, denied, disabled, 1280x800 light and 390x844 dark for every screen above.
- `features-page`: the Features page, one row per feature with what it holds and its switch, "Not set up" in amber, the
  off state, and the strength floor with its live sentence, Save and Undo.
- `feature-switches`: a unit's switches for Training, Critical tasks, Evaluations, Onboarding and Losses and awards, and
  its strength floor. Step 14 writes them through the Features page or `organization/settings` and proves what each
  switch hides.

## How to get to it (user POV)

Choose `Settings` in Organization navigation. The `Unit settings` nav groups the pages as Unit (`General`, `Features`,
`Policies`, `Ranks`), Access (`Members`, `Approvals`) and Records (`Archives`, `Exports`, `Logs` for owners), with
`Danger zone` (owners) below a rule. Below 768 px wide the same items show as tabs. Ranks belongs to the
[rank recipe](rank-settings.md). Archives failure states belong to the
[Personnel form recipe](personnel-form-states.md); step 5 covers its page. `Create Organization` and the Organization
list are on `/dashboard` (the account's home outside an Organization). An account with no Organization reaches the list
at `/dashboard?show=all`; plain `/dashboard` sends it to `/org/new`. Announcements appear as a banner above an
Organization's pages; `Send feedback` is in the Organization header at desktop widths, and at 390 it is in the account
pages' action row (sidebar name card → `Send feedback`).

## Driving it with verify:app

The [settings and destruction](organization-settings-destruction.md), [member access](organization-member-access.md),
[invitations](organization-invitations.md), [exports](organization-exports.md), [audit](audit-capture-projections.md),
[creation](organization-creation.md), [notifications and feedback](notifications-feedback.md),
[deletion request](deletion-requests.md) and [Dashboard](dashboard.md) recipes own data, permission, persistence,
cross-Organization and target-lifetime proof. This recipe adds presentation and state checks against the
[component contracts](component-foundation.md) and drives each persistence path only far enough to see its state.
Platform administration (`/admin/**`) has its own states run and is excluded. Record each cell PASS, FAIL, UNAVAILABLE
or UNRUN with the actor, width and theme. A defect stays FAIL until the same step passes on a later candidate.

Preconditions: owned launch and `doctor` pass; set `WORKER` and `V` per the index. Save `component-foundation.md`'s
state reader as `reader.js`. Use native `resize_page` (1280x800, 390x844) and the visible `Toggle theme` for dark
(`/dashboard` has its own; `/org/new` has none, so set the theme on `/dashboard` first and read
`document.documentElement.dataset.theme` after arrival). Start a keyboard step with `focus()` on the control, then press
real `Tab`, `Enter`, `Space` and `Escape`. Read the focus ring with `getComputedStyle` `outline` and `box-shadow` while
the control matches `:focus-visible` after a real key press: the app ring is the 3px `ring-ring/50` box-shadow; a UA
`auto` outline is the default ring, not the app ring. At each capture read `document.documentElement.scrollWidth`
against `innerWidth`, and for a horizontally scrolling region its own `scrollWidth`/`clientWidth`.

Actors (all from `$V fixture`): `orgOwner` (A owner), `orgAdmin` (A admin), `orgMember` (A member, Alpha),
`orgSettingsPeer` (B owner, Personnel none), `orgSettingsSwitch` (admin in A and B), `orgCreator` and `orgInvitee`
(confirmed, no membership), `deletionRequester` and `deletionReviewer` (A), `notificationMember` and `notificationOther`
(A). `$V actor ROLE dashboard` opens `/dashboard?show=all`, so `orgCreator` lands on the empty list rather than the
`/org/new` redirect. Read `$V rows organizations orgA` and `orgB` before and after every step that can write, and
`$V rows organization_invitations orgA` around Members. Leave every saved value as found: restore names, slugs and
policies through the same visible controls; revoke or decline UI-created invitations; never confirm `Delete permanently`
or a transfer.

Setup, in this order. `$V seed communications` (announcements and inbox rows). `$V seed deletion-sources`, then as
`deletionRequester` submit one pending A request for the seed's Personnel archival target through its visible Archive
confirmation (see the [deletion request recipe](deletion-requests.md) step 1); read
`$V rows deletion_requests orgA resource_id ID`. As `orgOwner`, invite `orgInvitee`'s email from `fixture`
(`invitationEmails.existingAccount`) through the Members invite strip so `Waiting on them` has a pending invitation and
the Dashboard has one for `orgInvitee`. `clean-seeds` at the end removes the seeded rows and the requests that target
them.

## Gotchas

- A network control matches only Organization A's endpoints, whatever page it is armed on. A held `deleteOrganization`
  still deletes A on release and an unarmed press on another Organization deletes that one unheld. Run Danger last: hold
  Transfer to `orgMember`, then `actor orgMember settings/danger` for the Delete hold.
- An action that redirects to a different page (a successful Transfer or Delete, to General or `/dashboard?show=all`,
  and a created Organization from `/org/new`) follows SvelteKit's app-wide navigation. Focus resets to the body and the
  route announcer reads the new page; that is not lost focus. The rule that focus never drops to the body applies to
  in-page actions. The held request is the busy state to check.
- `network arm-fail` is single use and binds A's current canonical segment. Restore after each case, and restore and
  rearm after a slug change.
- `network arm-hold` stays armed after its release; `network restore` before the next `arm-fail`, or the next arm is
  refused and the request goes through.
- Settings sections are server-loaded; there is no client workspace to hold. `settings-page/<tab>` and `audit-page` hold
  the section's page-data GET on a client navigation. A hover can prefetch and consume the one-shot control, so focus
  the tab and press Enter.
- General, Members and Danger form failures arrive as a real SvelteKit failure envelope with the action's error field
  (`error`, `slugError`, `inviteError`, `memberError`, `accessError`, `deleteError`, `transferError`); the request never
  reaches the provider. `arm-error` answers instead with an unexpected-error result (HTTP 500), which the page shows as
  an in-context `Alert` rather than the error page.
- Logs paging needs more than 25 entries; `$V seed audit` adds 105 to A.
- The Dashboard's `Organization controls` holds only search. Sweep it with
  `$V toolbar-sweep PAGE "<label>" RUN_DIR --no-fold --search --step 4`: nothing folds, search stays at every width and
  More never appears. The Dashboard toolbar needs the five Organizations from step 10's Filter row.
- Organizations created through `/org/new` have no cleanup control; worker cleanup disposes them.
- Members actions can require a recent sign-in; a fresh `actor` session satisfies it. A step-up redirect is a separate
  path owned by the [member access recipe](organization-member-access.md).
- The notification bell's states belong to the [notifications recipe](notifications-feedback.md).
- Feedback success writes a real row that no visible control deletes. Use one unique message; owned cleanup disposes it.
- Actors start with What's New dismissed; use `actor --show-whats-new` to see it.
- Decline the invitation on `/dashboard?show=all`. On plain `/dashboard`, declining an account's last invitation reloads
  into the `/org/new` redirect. `Invitation declined.` clears after four seconds; observe the status region from before
  the press.

For the stale feature shell check, leave Training Reports or Onboarding History open. In another authenticated session,
turn that feature off. In the stale tab, use a visible link to another server-loaded nested page. Require the exact
feature-off message and removal of that feature from the sidebar. A rejected API request uses the same message with
HTTP 403. Purely client-side Training tabs may retain data already loaded.
