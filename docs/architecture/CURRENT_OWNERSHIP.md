**Cross-owner SQL and transaction authority.** Organization's membership/Group scope facts feed Access Platform helpers and feature-owned RLS; the SQL `member_access_*` helpers read Organization membership data but do not create a TypeScript import from Access Platform into Organization. Personnel scope checks are used by Calendar, Training, Critical Tasks, Onboarding and Rating Scheme. The Sign-in Roster and sensitive-file helpers read Personnel scope while keeping their own record/path rules. Onboarding's `onboarding_template_training_type_matches` reads Training definitions. Leader notes use the [Organization-owned member-label read](../../src/features/organization/index.server.ts), scoped by the admitted Organization; the [shared contributor-label helper](../../src/lib/server/core/useCases/personnelArtifactLifecycle.ts) still directly reads `organization_memberships` for counseling, documents and follow-ups until their 08-M04 cutovers. [Organization provisioning](../../src/lib/server/adapters/supabaseOrgProvisioning.ts) calls `create_org_with_owner` for the Organization and owner membership, then separately seeds defaults through the current broad port; delivery composes Personnel Server for Group and rank seeds, while Calendar defaults remain in the adapter. Its use case imports Calendar holidays; Personnel owns the rank seed rows and provider write. The RPC's transaction does **not** make those later writes atomic. The remaining Calendar cross-owner defaults still need an owner seam; Organization retains its creation operation. Organization stores Group-scope IDs; Personnel owns the Group catalog, and storing those IDs alone is not a module import. Platform support projections read Organization memberships, Personnel counts and Audit records through privileged adapters. `reject_access_request_and_block_linked_invitations` is the Platform Administration transaction that updates Identity request and Organization invitation/link state together. Invitation acceptance locks/updates invitation and membership and touches Identity setup facts. The retained rank-delete RPC checks Personnel, Training and Sign-in Roster references in one database transaction; Calendar's assignment-type retention RPC must protect persisted assignment references. Rate-limit increments and auth-email sync rely on their effective SQL function/trigger transactions, not a TypeScript multi-call transaction promise. Data Export reads source tables, not ownership of their policies. Current broad `src/lib/server/core/ports.ts` and generic `supabaseDataStore` still let callers name foreign tables; D01 records that current placement, while D03/Phase 08 own actual cutovers.

**Intentional provider bindings.** Identity owns Supabase Auth account/admission semantics; Platform Administration owns privileged support commands. Current Organization member management also performs a privileged `auth.admin.getUserById` lookup in `supabaseOrgSettingsMemberManagement.ts` after `findUserEmailIdentityByEmail`; its `findUserAccountByEmail` result supplies invitation account/confirmation facts. This is an intentional current binding in Organization's adapter, not evidence that only Identity/Admin files call Auth admin today. The target Organization → Identity seam returns only those needed account facts through a narrow server lookup, keeping membership/invitation decisions Organization-owned and raw SDK access inside Identity's provider adapter. Organization invitation/provisioning SQL and membership FKs retain the same provider subject values. Access Platform owns current trusted membership/policy evaluation, not identity creation. Provider Infrastructure owns connection/service-role and PostgREST mechanics; feature-owned adapters map rows and errors without transferring policy ownership. Provider Storage Access owns shared `storage.objects` path/policy helpers; Personnel counseling/documents and Sign-in Rosters own their private-file business scopes. Supabase Realtime is configured, but this public catalog's publication record alone does not establish a current feature subscriber or hosted publication membership. Preserve effective RLS, function security/EXECUTE grants, Storage policies, auth triggers and current identifiers; the [trusted identity and access contract](AUTHORIZATION_AND_PROVIDER_BOUNDARIES.md#trusted-identity-and-access-contract-07-01c) states their current guarantees and D03/Phase 08 cutover direction. These bindings are current infrastructure, not abandoned compatibility paths or a future-provider migration plan.

## Observed dependency pressure

- Dashboard currently imports Calendar and Training mutable stores in `src/features/dashboard/dashboardWorkspaceHydration.svelte.ts`; its screen read model also reads Calendar stores and Rating Scheme calculations. Dashboard owns the composition, while those source owners retain data and policy.
- Onboarding currently imports Training store/types and scoped roster data in `src/features/onboarding/onboardingWorkspaceHydration.svelte.ts`. Training and Personnel remain the source owners.
- Server feature entry points still reach central `src/lib/server/core/ports.ts`, `src/lib/server/adapters/httpAdapter.ts` and central entities, for example `src/features/rating-scheme/server/ratingSchemeWorkspaceBootstrap.ts`. This is current placement, not evidence that the target public/server boundary exists.
- Routes deep-import feature contexts, stores, components and server bootstraps, for example `src/routes/org/[orgId]/calendar/+page.svelte` and `+layout.server.ts`. The D02 checker distinguishes declared public delivery imports from private imports and reports remaining violations; this ledger records their ownership without accepting them.

The [complete target import direction](MODULE_CONVENTIONS.md#chosen-module-and-delivery-contract-07-01d) also assigns current reverse dependencies: Personnel bulk-archive approval submission moves to server delivery composition; Resource Deletion Requests consumes source effects. Organization/delivery supplies administrator notification recipients. Audit delivery composes source-owned label/email reads instead of Audit importing event producers. These are declared cutover decisions, not claims that the current broad-store helpers already satisfy them.
