# D27 server policy and grant contracts

Issue [#1375](https://github.com/waffleflopper/trooptotask/issues/1375), task `08-M15-01p`. This intermediate deliverable moves shared server policy into Access, replaces policy-derived domain input types with an explicit portable Organization grant, migrates consumers, and removes replaced internal APIs. It preserves retained behavior. Request/provider composition, membership lookup duplication, cache/limiter placement and final integrated acceptance remain with D27. No migration is included.

## Declared scope

`OrganizationAccessGrant` carries the existing seven readonly actor/Organization/role/privilege/capability/scope facts. Thirty policy-derived feature contexts consume that grant or the existing narrow subset, with their required/optional audit needs preserved. Personnel's consumed roster actor name derives from the same grant. Shared policy uses only evaluated fields and `PolicyAuditSink`; it has no DataStore, aggregate context, Locals or provider dependency. The public Access barrel preserves consumed operations and exposes route/load authorization to delivery.

Seven generic policy modules and their old paths are removed together with every actual import. The unconsumed Personnel policy lookup, layout-only helper, privilege helper and public actor/grant override options are removed. Organization leave policy uses the same admitted actor directly. Feature, route, governance and self-owned denial messages/statuses and distinct audit shapes remain. Public authorization remains asynchronous, and loads authorize before executing their data operation. The request-local membership cache and ordinary provider boundaries are unchanged.

This PR groups the policy owner, grant contracts, callers and deletions because they implement one shared concern. Request/provider composition is a separate outcome that binds collaborators and changes their lifetime. That is the concrete reason it follows in another D27 PR.
