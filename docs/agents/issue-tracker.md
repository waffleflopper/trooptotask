# Issue Tracker: GitHub

Issues and PRDs live in GitHub Issues. Use the repository's configured GitHub remote; `gh` resolves it from the repo root. Confirm the target when multiple remotes make ownership ambiguous rather than using a hardcoded repository name.

Read an issue with `gh issue view <number> --comments`; use `gh issue list` to find relevant tickets. Reading context does not authorize creating, commenting on, relabeling or closing an issue.

For tracker writes, use authorization from the current request or an explicitly invoked workflow that includes publication. An incidental reference in a skill is not permission to publish. Prepare the exact title/body/labels locally before any approval needed for publication. Use a body file for multiline issue text and the [triage mapping](triage-labels.md) for labels.

An explicit owner activation of a named phase under [workflow #1275](https://github.com/waffleflopper/trooptotask/issues/1275) authorizes bounded stabilization tracker writes in `waffleflopper/trooptotask`: reconcile/create/update its deliverable issues, native parent links and milestone assignments, maintain concise progress, and close/reopen its parent/milestone only with verified acceptance/failure evidence. This supersedes the former blanket tracker-publication prohibition. Reading a ticket or setting up milestones alone does not activate a phase. Preserve human edits, inspect open and closed issues/PRs with pagination, reuse stable markers and verify native links by readback; failed access or ambiguous identity blocks advancement. Leave unrelated issues, coding-bot assignments and repository settings untouched.

GitHub owns issue relationships and actual PR/merge state; [TODO](../stabilization/TODO.md) owns local task mappings and the active checkpoint, and [EVIDENCE](../stabilization/EVIDENCE.md) owns detailed verification. Follow the [driver checkpoints](operating-rules.md#stabilization-tasks); implementing PRs close children, never the phase parent, and are not duplicate milestone deliverables. Tracker authorization does not authorize Git commit/push/PR creation, merge, release, deployment, remote SQL/provider administration, financial actions, live-data access or existing-local-database reset. Other communications still need authorization covering that action.
