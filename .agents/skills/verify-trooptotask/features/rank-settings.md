# Manage the rank catalog

An Organization owner or admin adds branch packs and custom ranks, edits and orders them, retires and reactivates them singly or by branch, and removes unused custom ranks; no other member can change the catalog.

## Sub-features

- `rank-detail`: the Ranks table's chevron discloses a rank's state, branch, category, pay grade, tie-break order, reference counts and warnings.
- `rank-filters`: search, the Active/Retired/All state buttons and the branch select narrow the table, report the shown count and name an empty result.
- `rank-create`: Add custom rank creates a new Organization rank that appears in Personnel's Rank selects once active.
- `rank-edit`: a custom rank's label, branch, category, pay grade, state and tie-break order are edited from its detail; its code stays fixed and built-in ranks have no edit form.
- `rank-order`: ranks sort by pay grade, then tie-break order, then code; there is no drag handle or move control.
- `rank-retire`: Retire hides one active rank from future selection and keeps existing Personnel, Training filters and history. Approved contract (#1600): Retire opens a confirmation first, Cancel leaves the rank active, Confirm retires it.
- `rank-reactivate`: Reactivate returns a retired rank to selection.
- `rank-bulk`: a branch pack's actions menu retires or reactivates every built-in rank of that branch after a confirmation; `Add <branch>` installs a missing pack.
- `rank-remove`: Remove permanently deletes an unreferenced custom rank after a destructive confirmation.
- `rank-failure`: a failed or rejected save shows its error, keeps every entered value and changes no row.
- `rank-denied`: a member without Organization owner/admin access cannot reach the catalog or change a rank.

## How to get to it (user POV)

Sign in as an Organization owner or admin, choose `Settings`, then `Ranks`. **Branch Coverage** lists each branch pack with `Add <branch>` and a `More actions for <branch>` menu. `Add custom rank` opens the form above the **Ranks** table. Each table row has a chevron `Show details for CODE` and an `Actions for CODE` menu. Personnel's Add Person and Edit forms read the active catalog through their Rank select.

## Gotchas

- `arm-fail` is refused while `arm-observe` (or any other control) is armed on the page; run `network restore` between modes, or the next confirm runs for real.
- Rank mutations are SvelteKit form actions on `settings/ranks`, not JSON endpoints. `network` binds them by action name and returns the failure envelope; `arm-observe` records the request without altering it.
- The table's default State filter is Active, so a retired rank vanishes from it. Switch to Retired or All before reading its state.
- Errors and successes return without naming the form, so the page attributes them to the last submitter. A server error after Add shows in the Add panel and one after Edit shows inside that row's detail.
- Built-in ranks cannot be edited or removed; only retired/active state changes. A referenced rank cannot be removed even when custom.
- Ordinary Retire is a single row action; the confirmation is the only guard for a rank that Personnel already use. Retiring never rewrites those Personnel.
- A branch pack, once added, stays in the catalog. Prefer the Remove action for each unreferenced row or restart the owned worker; do not edit rows through the provider.
