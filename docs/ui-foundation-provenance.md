# Web foundation provenance and family contracts

This reference records the foundation and its contract for Phase 09 D01 [#1579](https://github.com/waffleflopper/trooptotask/issues/1579). The token source, theme source and Bits UI upgrade below are implemented. D02 [#1580](https://github.com/waffleflopper/trooptotask/issues/1580) has deleted the selected unused families, alias barrels, dead DataTable helpers and the RangeCalendar patch. Its layer moves are in progress.

## Source and comparison method

The source snapshot is `49480d1d2d616504d72ecc72c5e469f45bfb3d21`, whose application tree matches accepted main `8072a9efbfb3438da415ac6681eeee8666b44860`. `components.json` selects Nova, Stone and the `$lib/components/ui` alias. It does not pin a registry. No shadcn-svelte CLI is installed in package.json or the lockfile. The catalog's generation-time CLI reference is 1.2.7, not an installed dependency.

The comparison reference is the [shadcn-svelte 1.2.7 tag](https://github.com/huntabyte/shadcn-svelte/tree/4de0a05f149a3f9f4fb10016dea3ea62b4e9b760/docs/static/registry/styles/nova). A fixed upstream revision makes the comparison repeatable. It establishes source correspondence, not the historical command that generated each file. The [registry configuration](https://shadcn-svelte.com/docs/components-json#registry) explains why an unpinned live registry can change independently of a CLI version.

The audit reads each matching Nova registry JSON into disposable scratch output. It expands `files[].target`, resolves `$UTILS$`, `$UI$`, `$HOOKS$`, `$LIB$` and `$COMPONENTS$` to the configured aliases, then formats both source copies with the repository's Prettier configuration. It compares the union of production `.svelte` and `.ts` filenames, excluding test files and test-only fixtures. It never generates over working files. Icon-template replacement remains a recorded installation difference rather than being hidden by normalization.

- **Stock** means the compared production file set and formatted bytes match after those alias substitutions.
- **Adapted** means a matching registry family exists, but its production files differ. The named differences and their retained purpose appear below.
- **Project composition** means the project owns the family API. A composition may retain registry helpers without becoming a stock primitive.

The source has 63 family directories, plus `ConfirmDialog.svelte` and the standalone `OverflowMenu.types.ts`. Tests and harness files at the `ui` root are verification support, not additional public families. [D01 evidence](stabilization/EVIDENCE.md#phase-09-d01-foundation-provenance-and-contracts) links the complete normalized comparisons, source graph, installed-version snapshot and archive integrity check.

## Layers and API rules

These are the selected layers. Current imports remain valid until the owning migration updates every consumer.

- `src/lib/components/ui` owns canonical web primitives and central appearance variants.
- `src/lib/components/patterns` will own shared, domain-neutral compositions justified by current consumers. D02 creates that directory. Patterns compose primitives and do not become another primitive library.
- Feature presentation stays with its module's current web implementation. Domain-specific status and calculation inputs do not belong in neutral shared controls.

The public family barrel is the canonical import API. Import its exported components, types and helpers. A component's internal files are implementation details. Existing `Root` and descriptive aliases in the same barrel are the same implementation, not two foundations. Preserve public props, bindings, snippets and events unless the mapping below names a replacement. Do not infer upstream support for props the local API does not expose.

Feature/server operations remain authoritative for validation, authorization and persisted state. Shared fields associate labels and errors and show caller-provided validation results. They do not decide feature policy.

## Token and theme contract

- `themeStore` owns the app theme. Its pre-paint `app.html` script uses the same `theme` storage key and `data-theme` attribute. Sonner reads `themeStore.current`; mode-watcher is removed. Theme selectors and Tailwind's dark variant match only `[data-theme='dark']`.
- `src/app.css` keeps raw values in `:root` and the `data-theme='dark'` block. Each `--color-*` mapping is declared once in `@theme inline`, including derived chrome mappings with unchanged formulas. Chrome values are identical across themes and are declared only in `:root`. The unconsumed public-frame glow/shadow mappings are deleted.
- `--warning`, `--success` and `--info` are separate from brand/chart tokens. `--accent` remains brand/highlight amber. Warning is `oklch(66.6% 0.179 58.318)` in light and the Training print override, and `oklch(76.9% 0.188 70.08)` in dark. Success is `oklch(62.7% 0.194 149.214)` and info is `oklch(58.8% 0.158 241.966)` in both themes. Status mappings keep their muted-background formulas. Other print paths retain their current theme behavior.
- Status text uses distinct raw `--danger-foreground`, `--warning-foreground`, `--success-foreground` and `--info-foreground` tokens, mapped once to the existing `--color-*-foreground` names; fills, muted backgrounds, `--destructive`/`--destructive-foreground` and `--accent` are unchanged. Light and the Training print override use red-700 `oklch(50.5% 0.213 27.518)`, amber-800 `oklch(47.3% 0.137 46.201)`, green-800 `oklch(44.8% 0.119 151.328)` and sky-700 `oklch(50% 0.134 242.749)`. Dark uses red-400 `oklch(70.4% 0.191 22.216)`, amber-500 `oklch(76.9% 0.188 70.08)`, green-500 `oklch(72.3% 0.219 149.579)` and sky-400 `oklch(74.6% 0.16 232.661)`.
