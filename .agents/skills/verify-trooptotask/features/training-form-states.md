# Dashboard and Training: raw controls, failed saves, field errors and screen states

A member whose Training save fails keeps every value they entered and sees where the error belongs. Every Dashboard and Training screen has a clear loading, empty, error, denied, disabled, narrow and dark state, and each hand-built control exposes its name and state.

## Sub-features

- `raw-control-baseline`: the plain `<button>` controls that the canonical foundation will replace expose a name, a role, keyboard operation, a visible focus ring and a state. This recipe records what each one does today so a cutover can be compared control by control.
- `failed-save-keeps-values`: a rejected save leaves the form open with every value, selection and chip in place, the saved row unchanged and an explicit retry that saves once.
- `field-error-association`: a validation or save error is rendered by `Field.Error`, the control is `aria-invalid="true"` and its `aria-describedby` resolves to the message. A raw `<p>`, a toast or text inside a row status is recorded as a baseline failure.
- `screen-states`: loading, empty, error, denied, disabled, 1280x800 light, 390x844 dark, keyboard and focus, and URL state for the Dashboard and the Training screens.
- `data-color`: a Training type color is stored data. A literal hex in source is a style default and must not replace the stored color.
- `table-semantics-and-print`: the Type risk table and the three print tables expose headers and scope, and print preview renders them.

## How to get to it (user POV)

Dashboard: sign in, enter an Organization and choose **Home**. Training: **Training** in the sidebar, then **Manage Types**, **Manage Views**, **Reports**, **Import**, a Person's name (the `Training Records` dialog) or a matrix cell (the `Add Training Record` or `Edit Training Record` dialog).

## Driving it with verify:app

Preparation status: the observed results below were measured on the unchanged baseline in the `1602-baseline` run (main `3cf35215e`). They are a record of what the app does, not a statement of what it should do. Expected behavior comes from the [foundation contract](../../../../docs/ui-foundation-provenance.md#canonical-category-mapping), the [component contracts](component-foundation.md) and the issue acceptance. Record each cell PASS, FAIL, UNAVAILABLE or UNRUN with the actor, width and theme. A reproduced defect stays FAIL until the same step passes on a later candidate. This recipe adds what the [Dashboard](dashboard.md), [Training catalog and views](training-catalog-views.md) and [Training completions](training-completions-reports.md) recipes do not state. Their data, permission and scope steps stay authoritative.

Preconditions: owned launch and `doctor` pass; use the index's `WORKER`, `V`, fresh snapshots and evidence directory. Save `component-foundation.md`'s state reader as `reader.js`. Run `$V seed dashboard-overflow` for the Dashboard buttons and clean it with `clean-seeds` before the Training steps, because seeds change the matrix and the Reports numbers. Use unique `Baseline<tag>` names for every draft. Dismiss the `What's New` dialog (`Got it`) on each actor's first load before any capture. Starting a keyboard step with `focus()` on the control and then pressing real keys is faster than counting Tab presses. The key names are `Enter`, `Space` and `Escape`. Every failure uses a synthetic undispatched 503 from `$V network arm-fail`, which proves client recovery only. Run `$V network restore PAGE` after every case: an armed hook that has already matched does not re-arm, and the next save then succeeds.

## Gotchas

- The shadcn `Select` options do not appear in the accessibility snapshot. Open the control and use ArrowDown and Enter.
- `network arm-fail` is single use. Run `network restore` after each case and before re-arming.
- A PDF capture from the print helper counts its own `beforeprint` and `afterprint` events. Read `print state` after the button click and before the save.
- `seed dashboard-overflow` and `seed dashboard` change the Training matrix and Reports. Clean seeds before reading the unchanged Training numbers.
