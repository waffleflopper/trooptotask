## Execution rules

- Retained contracts R1–R8, inventory M01–M17 and defects F01–F11 refer to [BASELINE.md](BASELINE.md). Its `UC/`, `AD/`, `EN/`, `ORG/` path abbreviations apply here. “Tests” means adjacent behavioral tests for owned files, not unrelated suites.
- Every task owns one behavior or boundary. Resolve imports and callers in the same task; delete the obsolete implementation, do not leave compatibility facades. A feature inventory row is not permission to rewrite its whole workflow at once.
- **G** = `npm run format`, `npm run lint`, `npm run governance:check`, `npm run check`, `npm run test` after implementation. Record pre-existing failures until repaired; they do not count as a passing gate. Build where boundary/bundle changes warrant it. Do not inflate thresholds, add allowlists, reduce scan scope, skip assertions or change expected outcomes to obtain green checks.
- **DB** = separately authorized, isolated disposable stack with synthetic fixtures and a distinct project/port allocation, never the existing 543xx/553xx/563xx stacks. Read lifecycle/seed scripts first; never load the legacy seed dump. Verify fresh replay and upgrade from the audited migration chain, positive/negative RLS, SQL functions/grants/triggers/FKs and retained row identities. No remote DB access or existing-local reset/modification. Record exact tool versions/commands/results. Clean up only resources created for that verification.
- A task closes only when its stated verification and measurable acceptance pass, owned obsolete consumers are gone, and these documents record evidence. Historical migration text is not an active object; live compatibility code is not historical documentation. Keep append-only migration provenance; no wholesale port from v2.
- Phases 08 and 10 have complete inventories rather than pretending every distant implementation detail is known. Immediately before each inventory item, expand it into suffix tasks (`08-M05-01`, etc.) with prerequisites, exact files/symbols, outcome, retained contracts, deletions, checks and acceptance. Complete every suffix and every inventory row. Do not mark a phase complete after one example. Apply the same expansion to distant phases 11–15 when their prerequisites expose the final paths.
- Data uncertainty blocks only the affected deletion. Preserve stored Calendar facts and referenced types by default; proceed with runtime removal and safe schema planning. Production deployment, remote migrations, merge, publication and communications remain unauthorized throughout this queue.
