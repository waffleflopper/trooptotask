**Method.** `npm run verify:app -- restart` built and previewed production on the owned disposable provider, worker 1. `seed workload small|typical|large` created 20, 100 and 400 active People, plus about 10% archived, from the table in `helpers/perf-workloads.mjs`. First useful render runs from navigation, or from the first trusted input event, to the first frame where the journey's milestone text is present and no skeleton remains. Settled including reloads then waits for the app origin to go quiet for 500 ms, with every started `__data.json` finished, and takes the later of first useful render and the last document or data response end. Manifests, server timing and statements are read only after that idle point. Each sample gets its own pg_stat_statements window. It is reset immediately before navigation for a load, and after the page is idle immediately before input for an interaction, so setup navigations stay outside it. Resource entries, network requests (bytes transferred) and failed responses are counted separately. A cold context starts on a blank page whose automatic favicon request redirects to `/auth/login`, which preloads the shared entry CSS and JS. Cold samples therefore count about 31 shared entry assets as cache hits, as for any visitor arriving through sign-in. Distributions are min, median and max over every sample; no p95 is reported.
