## Grounding and design

Two independent same-model readers traced membership/admission and provider/consumer composition on unchanged `ee1ca2b2`. The three builders repeat a 35-field catalogue. Every field has a real consumer, but specialist collaborators normally serve one operation family. The preloaded-membership builder has no production caller. The old permission constructor has no caller, and Identity's grant getter construction has one runtime consumer through HTTP.

The selected design makes the context builder explicit in each route/load configuration and returns the owner's existing narrow contract. A delivery-only request carries admitted grant, audit, ordinary client, scoped/raw stores and session facts needed for binding. It carries no feature catalogue. Selected builders import public server contracts and operations. Direct aggregate-builder callers migrate to explicit builders. The alternative binds every operation into a new input-only closure; it adds wrappers and changes more testing seams without a current need. Extracting one common 35-field constructor was rejected because it retains the facade.

Provider constructors allocate objects and closures; they do not eagerly query feature data or acquire admin clients. No latency or query improvement has been measured. Current `getAdminClient` creates a new SDK client per invocation. Request-local reuse is considered only if the chosen binding needs it and preserves lazy acquisition; it is not an accepted optimization claim.

HTTP and Shell share the same request cache. The first loader determines the shared row or rejection. HTTP currently maps a returned membership-provider error or absent row to its existing 403. Organization's Shell reader distinguishes provider error as 500 and absence as its existing 403. Malformed member presets fail rather than become an editor grant. These public differences must survive any source-read consolidation. Rejected loads evict only their own current promise and permit retry; later requests see revoked membership.

Throughput checkpoint. The coordinator owns all source/contracts/manifests, worker 1, native driving and evidence. Bounded workers first traced unchanged source, then implemented exclusively assigned source/test slices; none drove a browser or provider. The coordinator owns integration and live evidence. Fresh independent reviewers did not author these slices. Existing feature recipes, actors, recorded provider reads and capture controls supply proof. Freeze executable source and driving instructions during each run. Group the full shared composition concern rather than creating a PR per field or reviewer finding.
