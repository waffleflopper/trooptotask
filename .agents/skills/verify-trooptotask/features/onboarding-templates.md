# Onboarding templates and configuration

An Organization Onboarding configurator defines reusable checklists with checkbox, paperwork and Training steps. Definitions are shared within the Organization; configuring them requires Organization scope and works without Personnel or Training capability.

## Sub-features

- `templates`: create, rename, clear nullable descriptions, cancel, duplicate and delete a template while preserving retained packet snapshots and unrelated definitions.
- `steps`: create/edit/delete checkbox, paperwork and Training steps; preserve ordered paperwork stages and same-Organization Training references; reorder without changing step identity.
- `lookups`: Onboarding receives scoped Personnel references and Organization Training labels through their owned lookup seams, independently of those lanes' grants.
- `access-and-recovery`: Organization-scoped configure permits definition writes; view/operate and Group-scoped configure cannot mutate the catalog. Foreign references and stale Organization responses cannot cross Organizations. Failed requests need visible feedback, retained drafts and real retry.

## How to get to it (user POV)

Choose `Onboard` in Organization navigation, then `Templates`. Select a template in the list; use `Add Template`, the named edit/duplicate/delete buttons, and `Add Step`. `Onboarding` returns to the packet workspace; `History` opens retained packets. The direct `onboarding/templates` route requires configuration authority; view/operate members read shared definitions through the ordinary Onboarding workspace and its template labels instead.

## Gotchas

- Approved Onboarding configure is Organization-scoped. Configuration navigation, direct page admission and template/step mutations must all require Organization scope. The unchanged baseline exposed unscoped controls/reorder admission; compare the repaired UI/request/stored-row outcomes against that recorded failure.
- The workspace retains mutation errors internally; only a rendered message establishes user feedback. A synthetic503 is client delivery proof, not partial-provider transaction proof.
- Select portal options may be absent from accessibility snapshots. Inspect rendered options read-only and use focused arrows/Enter; verify the selected label and saved reference.
- Use focused keyboard deletion for bound text clears. A native fill of an empty string alone may clear the DOM without updating the Svelte draft.
- Seeded packet progress is a retained snapshot. Do not require automatic resync or expand this recipe into D15's full packet lifecycle or D12's Personnel creation.
- Restore armed network/feedback controls and UI edits; delete UI-created rows visibly/read back absence. `clean-seeds` removes only helper-created rows. Finish with owned cleanup and verify artifacts survive.
- Existing installed-SDK persistence/CRUD/query/workspace/page/duplicate tests and `supabase/tests/onboarding_template_rls.sql` establish distinct lower-level boundaries; neither source review nor direct API proof replaces visible interaction.
