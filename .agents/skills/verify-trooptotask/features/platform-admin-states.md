# Platform admin: raw controls and screen states

The platform operator can reach every admin control by keyboard, sees which page, row or panel is current or expanded,
keeps entered values after a failed save, and gets a clear loading, empty, error and denied state on every admin page
and modal at desktop and phone widths, in light and dark.

## Sub-features

- `shell`: the dark admin sidebar with the `TroopToTask` wordmark and `Platform` label, its current-page state and Inbox
  open-count badge, the operator block with `Back to the app`, the top bar breadcrumb, and the `Menu` disclosure below
  1024 px; no focusable control without an action.
- `search`: the global `Search platform admin records` command palette with its searching, empty, failed and result
  states, keyboard selection and a single instance per width.
- `admission`: only the operator at MFA level aal2 enters `/admin`; an operator at aal1 is sent to MFA; every other
  account is denied.
- `inbox`: the `/admin` home; its queue, detail and states are owned by [Platform Inbox](platform-inbox.md).
- `directories`: Users and Organizations search, filters, row count and paging held in the URL, with empty and failed
  reads.
- `records`: User and Organization detail, account-support buttons, the disabled own-account `Suspend User`, and the
  `SuspendModal` (with its MFA step-up) and `TransferOwnershipModal` dialogs with focus entry, focus return, busy and
  failed-save states.
- `announcements`: the create form, Activate or Deactivate, the Delete confirmation, failed create and
  `Reload Announcements`.
- `audit`: Action and Severity filters and paging in the URL, the `Collapsible` details disclosure and empty and failed
  reads.
- `screen-states`: loading, empty, error, denied, disabled, 1280x800 light and 390x844 dark for every admin page and
  modal.

## How to get to it (user POV)

Sign in as the platform operator, enter the authenticator code and open `/admin`. The sidebar lists Inbox,
Organizations, People, Activity and Announcements (People and Activity answer 404 until their slices land; Users and
Audit Log keep answering at their old paths). From 1024 px a dark sidebar holds the sections, the operator's email with
`Operator · MFA on` and `← Back to the app`; the content sits in a light panel whose top bar holds the breadcrumb
(`Platform › Inbox`) and the global search (`Find a person or organization`, `⌘K`, or `Ctrl K` off a Mac). Below 1024 px
a dark top bar holds the wordmark and `Menu`, which opens the same sections and operator block; below 640 px the search
moves into `Menu` too. Follow `Inspect` on a User row or an Organization name to open its detail, where the operator has
`Suspend User`, `Suspend`/`Unsuspend` and `Transfer Ownership`. Suspending asks for the authenticator code again when
the last one is older than 10 minutes.

## Driving it with verify:app

The [platform administration](platform-administration.md), [platform support content](platform-support-content.md) and
[notifications and feedback](notifications-feedback.md) recipes own data, permission, persistence, stale-response and
step-up journeys. This recipe adds the presentation and state checks they do not state and does not repeat their
mutations or direct HTTP proof. Record each cell PASS, FAIL, UNAVAILABLE or UNRUN with the actor, width and theme.

Actors: `platformReviewer` is the platform operator and the only account with a `platform_operators` row. It has a
verified authenticator, and `actor` signs it in at aal2 through the provider (the helper completes the TOTP and stores
that session, so the page opens directly). `$V actor --aal1 platformReviewer admin` keeps the password-only session,
which the app sends to `Enter your code`; `$V actor --stale-mfa platformReviewer admin` signs in at aal2 with an
authenticator verification 11 minutes old, which the suspension check rejects until the code is entered again.
`$V mfa-code PAGE platformReviewer "Verification Code"` types the current code on the MFA page, which submits itself.
`platformSupport`, `platformBilling`, `platformInactive` and `orgMember` hold no operator row and are the denial actors.
`$V actor ROLE admin|admin/users|admin/organizations|admin/audit|admin/announcements` signs in a new context. Seeds, in
this order: `$V seed platform-admin` (temporary Organization, `orgCreator`/`orgInvitee`/`orgMember` memberships, two
pending requests, one completed approved request and the unconfirmed account `platform-pending-TAG@example.test`), then
`$V seed audit` (105 same-action A events); `$V seed organization-pages` (30 extra Organizations named
`Paging verification TAG NN`, removed by `clean-seeds`) only when the Organizations paging cell runs.
`$V platform-state` reads the platform seed's rows. Run the announcement Empty cell before any announcement exists;
`seed communications` is not needed for this recipe.

Preconditions: save `component-foundation.md`'s state reader as `reader.js`. Use native `resize_page` (1280x800,
390x844) and, for dark, the visible `Toggle theme` on `/dashboard` before opening `/admin` (the admin shell has no theme
control and follows the saved theme); the theme is per browser context, so set it once per actor and read
`document.documentElement.dataset.theme`. Start a keyboard step with `focus()` on the control, then press real `Tab`,
`Enter`, `Space`, `ArrowDown` and `Escape`. For the focus ring read `getComputedStyle` `outline` and `box-shadow` while
the control matches `:focus-visible` after a real key press. The app ring is a Tailwind `ring` box-shadow
(`ring-ring/50` 3px on `Button`); the sidebar links, `Menu` and `Back to the app` use a 2px `outline-ring` outline; a UA
`auto` outline is the default ring, not the app ring. At each capture read `document.documentElement.scrollWidth`
against `innerWidth` and the main region's `scrollWidth` against its `clientWidth`. Page-data failure and hold use
`$V network arm-load-error|arm-fail|arm-hold PAGE admin-inbox-read|admin-users-read|admin-organizations-read|admin-announcements-read|admin-audit-read|admin-user-detail-read|admin-organization-detail-read`;
arm on another admin page, then follow the visible sidebar link. Focus the link before arming so a hover prefetch does
not consume the one-shot fault, and `network restore` after each case. `arm-load-error` returns the real read with its
page node replaced by a 503 server-load error, which renders the admin error page inside the admin navigation;
`arm-fail` fails the whole `__data.json` request, which SvelteKit always sends to the site-wide error page.

## Gotchas

- Admin pages load on the server. Page-data controls fail or hold a SvelteKit client navigation only; a full reload is
  not intercepted. Arm, then use a visible sidebar link.
- `admin-access/*` and `admin-transfer` need `seed platform-admin` first.
- `clean-seeds` refuses a remaining seeded suspension; restore any suspension visibly first. Feedback rows have no
  delete and stay until worker cleanup.
- A failed suspend or transfer marks the dialog uncertain; it closes only through `Reload details` and then `Cancel` or
  a matching current state.
- Toolbar fold sweeps, as `platformReviewer` with the page already open: `Users controls`
  `--no-fold --pinned access-requests --search`; `Organizations controls` `--expect rows,status --search` (`Rows` folds
  at 392px); `Audit Log controls` `--expect severity,action --to 240` (`Severity` folds at 280px);
  `Announcements controls` `--no-fold --pinned create`; `Organization controls` `--more-always --pinned transfer`;
  `User controls` on a confirmed account `--more-always --pinned reset-password`, and on the pending account
  `--more-always --expect resend-invite --pinned reset-password --to 244` (`Resend Invite` folds at 352px). The last two
  keep `More` at every width because `Suspend` is `menuOnly` for another account. On the operator's own account
  `Suspend User` is a disabled row button instead, so `User controls` has no `More` there.
- The suspension check reads the authenticator verification time from the session, so a session at aal2 for more than 10
  minutes needs the code again. `actor` makes a fresh aal2 session, which stays valid for a suspension for 10 minutes;
  `--stale-mfa` skips that wait.
