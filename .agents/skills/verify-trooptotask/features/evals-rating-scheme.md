# Track evaluations and evaluator relationships

Members use Evals to track rated individuals, evaluators, rating periods, report types and workflow progress. Rating Scheme access is independently grantable without Personnel access. This recipe owns D16 [#1364](https://github.com/waffleflopper/trooptotask/issues/1364) browser coverage; it does not establish the later ownership cutover.

## Sub-features

- Grouped/table views; evaluation type, record status and workflow filters.
- Add/edit with internal or external raters, optional intermediate rater/reviewer, annual dates, notes and separate workflow status; save/cancel and reload persistence.
- Overdue, 30-day, 60-day and current due calculations, completed exclusion and the Organization Dashboard due projection.
- Actual filtered Rating Scheme workbook, including evaluator names, dates, due/status/workflow labels and notes.
- Dedicated view/operate/configure access, Alpha/empty-Group/unassigned and foreign Organization isolation; permission narrowing when switching Organizations.
- Direct deletion for admins/owners, approval submission for ordinary operators and Rating-owned approved effects; failed saves/deletions/requests must report failure and support recovery without losing the current draft.

## How to get to it (user POV)

Sign in, choose the Organization and open **Evals** from its navigation. Switch between **Grouped** and **Table**, then use the evaluation filters. **Add Entry** opens a new draft; select an existing row to edit. **Export** downloads the currently filtered entries. Return to the Organization Dashboard through its visible navigation to inspect upcoming evaluations. A member with Personnel access alone cannot enter Evals.

## Gotchas

- Configure does not grant governance deletion: an ordinary configure member still requests approval; owner/admin direct removal remains separate.
- `ratingForeign` operates its own Organization B; its requests into A must be denied. It is not a view-only B actor. `ratingSwitch` operates A and views B. Before mutation probes, establish the actual fixture role, admitted Organization and target ID, then derive the expected result from those grants. Keep B’s original full row as an untouched sentinel; do not use it to test an assumed denial. Use the admitted view-only actor for B write denials.
- The active Personnel reference lookup deliberately excludes archived People while RLS retains assigned archived evaluation records. Observe the saved ID and unknown-label behavior; never treat a missing label as a missing entry.
- Due dates use browser-local midnight. Use the fixture/browser date and record the actual timezone; rerun dated expectations if the run crosses midnight.
- Workbook export is a client download, not a Rating Scheme export endpoint. Organization Data Export and deletion-review effects are consumed reverse seams covered above; Data Export/D18 retain orchestration. Rating has no separate retention family; Person/Organization cascades and historical evaluator deletion limits remain separate contracts.
- A client-injected 503 proves visible response handling, not provider rollback, atomicity or real delivery. Authenticated HTTP and SQL observations remain separately identified.
- Approved Rating deletion keeps the request-authenticated provider. Separately probe an admitted synthetic admin downgraded to a viewer immediately before the real database DELETE: its own pending request may stay readable, but the evaluation must remain unchanged and approval must not report success. Restore the exact membership before a positive retry. This is an isolated provider/owner-operation check, not a browser-held-response or atomic review claim.
- Keep expected permission and tenant guarantees independent of observed output. A verification-only PR can expose a failing baseline while leaving its repair/cutover acceptance open.
