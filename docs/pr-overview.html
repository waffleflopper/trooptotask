00The big picture

Every change here pushes domain rules down into small, testable, provider-free modules and pulls incidental wiring out of the UI. The headline win is performance: the org page used to block its first paint on notification counts and the full organization list. Now it blocks only on what the screen actually needs to render correctly.

01App Shell first-paint split

The largest change. The old OrgShellData was a flat bag of ~20 optional fields that mixed access-critical identity with cosmetic chrome (notification badges, the org switcher list). Rendering had to wait for all of it. This commit replaces it with a small discriminated union and moves the cosmetic parts behind an on-demand endpoint.

The shape of the data changed

Before — flat bag, everything optional
interface OrgShellData {
  orgId: string;
  orgUrlSegment?: string;
  membershipId: string | null;
  userId: string | null;
  userRole: 'owner'|'admin'|'member';
  // …access fields…
  unreadNotificationCount: number;  // blocks paint
  allOrgs: Array<…>;            // blocks paint
  orgSuspended?: boolean;        // ambiguous
}
After — union: you can't read a suspended org's data
interface ReadyAppShell {
  kind: 'ready';
  org: { id; urlSegment; name };
  user: { id };
  member: { role; capabilityMap; … };
  state: { effectiveTier; isReadOnly;
           orgSuspended: false };
  preferences; announcements;        // layout-stable
}
interface SuspendedAppShell {
  kind: 'suspended'; org; state;  // no member data
}
type AppShellRouteData =
  { shell: ReadyAppShell | SuspendedAppShell };
Type-safety win: a suspended org no longer carries half-populated member/permission fields. Code that needs them calls requireReadyAppShell(), which narrows the union (or throws 403) — so "is this org usable?" is checked once, not re-guessed at every ?.

Ripple: ~30 routes simplified, 3 modules deleted

Every +layout.server.ts and settings loader that used to destructure { orgId } from a loosely-typed parent now consumes the typed shell. The old loadOrgShell.ts, its test, and the loadRoot coordinator path were deleted — and two compatibility-adapter entries were removed from GOVERNANCE_BASELINE.json, meaning the transitional debt they tracked is genuinely gone.

04Stale Supabase auth handling

When a Supabase refresh token goes stale (rotated, expired, or already used), getSession() / getClaims() can throw — and an unhandled throw in hooks.server.ts surfaces as a hard 500 on an otherwise normal page load. This commit catches the known stale-auth codes, clears the offending cookies, and degrades to a clean signed-out state. 

const STALE_SUPABASE_AUTH_ERROR_CODES = new Set([
  'refresh_token_not_found', 'refresh_token_already_used',
  'session_not_found',        'session_expired'
]);

await event.locals.supabase.auth.getSession().catch((error) => {
  if (isStaleSupabaseAuthError(error)) {
    clearSupabaseAuthCookies(event);     // remove the bad cookies
    return { data: { session: null }, error };  // degrade, don't crash
  }
  throw error;                            // genuine errors still bubble
});

Before

Stale token → uncaught throw → 500 error page. User is stuck until they manually clear cookies.

After

Stale token → cookies cleared → treated as signed out. User lands on login and recovers on their own. Covered by a new hooks.server.test.ts.

05Import callback cleanup

A small but honest cleanup: the bulk-status import flow carried a completion callback that, after the availability refactor, no longer did anything the parent didn't already handle. Removing it trims dead wiring from BulkStatusImport and BulkStatusPage.

Dead code removed, not deprecated. The kind of change that keeps a refactor honest — leftover scaffolding gets torn down rather than left to confuse the next reader.
