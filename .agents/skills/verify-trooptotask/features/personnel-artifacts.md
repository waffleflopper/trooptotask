# Manage Personnel artifacts

A member records follow-ups and leader notes, uploads counseling PDFs and other documents, and manages each Soldier's retained history through archive, restore, export and scheduled retention.

## Sub-features

- `artifact-entry-points`: the Personnel dashboard previews and dedicated Follow-ups, Counselings, Documents, Notes and Archived tabs retain the same Person identity.
- `artifact-create-retry`: failed saves retain text, dates and selected files; visible retry creates one saved artifact and reload shows its submitted fields.
- `artifact-follow-ups`: create and edit title, notes and due date; complete, reopen, archive and restore while retaining the saved identity.
- `artifact-counseling`: upload a completed session's PDF, conducted date, title and optional summary without adding signature tracking or a counseling form workflow.
- `artifact-documents`: upload supported files within the file and per-Soldier storage limits, derive or edit the title, and open the authorized saved file.
- `artifact-notes`: create and read the accepted leader-note shape, preserve contributor-label fallback and archive/restore behavior.
- `artifact-lifecycle`: archive individual items, restore or permanently delete them from Archived, and retain the parent archive event and unrelated historical items.
- `artifact-sensitive-scope`: distinguish configure reads from operate writes, authorized Alpha from Bravo/unassigned/empty scope, and the requested Organization from a foreign Organization.
- `artifact-export`: preserve raw Organization export rows separately from readable workbook projections and the existing narrower single-Person workbook.
- `artifact-retention`: delete only expired archived artifacts, remove files for deleted rows, preserve active/recent/foreign sentinels and report truthful counts and failures.
- `artifact-switching`: a Person or Organization change and late responses cannot carry the previous record's draft, saved items or file access into the next record.

## How to get to it (user POV)

Choose Personnel, find a Soldier and select Details. The Dashboard provides Follow-up, Counseling PDF, Document and Leader note forms and recent-item previews. Use Show all or the detail navigation's Follow-ups, Counselings, Documents and Notes tabs for their complete lists. Follow-ups supports Edit, Complete/Reopen and Archive; Counselings, Documents and Notes provide Archive. Documents provides Open. Archived combines all four families and provides Restore and Delete for each item.

The header's Upload PDF link opens Documents; it does not open the Counseling form. Counseling cards show the filename but currently provide no Open or download action. Do not invent a native counseling-file journey. Its authenticated Storage access is a separate provider/security obligation.

Use Dashboard → Export records for the single-Person workbook. An Organization owner/admin uses Settings → Exports for complete Organization JSON and Excel, and Settings → Archives for parent Personnel restore. Scheduled retention has no user-facing run button; its admitted job call and provider/file effects are separate from the visible Archived list.

## Gotchas

- Archive, Open, Restore and Delete repeat per item. Use a fresh snapshot and the named row; preserve the selected ID alongside the action. Delete currently acts directly without a confirmation dialog.
- The recorded outcome comes from visible actions plus saved row/file readback and reload. A closed form, disappearing card, signed URL or success toast alone is insufficient.
- Counseling file access has no current native entry point. Label authenticated Storage/SQL proof honestly; do not add an Open product feature merely to make the recipe executable.
- The [retained file rules](../../../../docs/domain/retained-feature-rules.md#personnel-documents-and-counseling) and [sensitive authorization contract](../../../../docs/architecture/AUTHORIZATION_AND_PROVIDER_BOUNDARIES.md#feature-permission-direction) own expectations. Keep the accepted note author fallback and 100-row composite-cursor traversal with complete legacy arrays; a small native list does not re-prove tied-timestamp or large-collection coverage.
- File upload rollback and delete cleanup cross Storage/database calls. Direct archived item deletion removes the row before its file. Organization-approved counseling deletion removes the file before its atomic request/record RPC; file-bearing deletion races remain the recorded D18/RELEASE obligation. Do not claim a durable workflow redesign or transaction around Storage.
- Preserve meaningful lower-level checks: the current same-name counseling/documents/follow-ups/archived-artifact use-case tests; Personnel `personnelArtifactRetention.server.test.ts`, `artifactWrites.server.test.ts`, `leaderNotes.server.test.ts`, `governanceDeletion.server.test.ts`, `personnelArchiveCascade.server.test.ts`, `personnelExport.server.test.ts` and `organizationExport.server.test.ts`; artifact draft/workspace/component tests; counseling/documents/notes page tests and artifact JSON/download route tests. Keep tests with the owning operation when cutover moves it; source-mirrored spec-registration tests are not behavioral acceptance.
- Run isolated SQL through the [Definition of Done](../../../../docs/architecture/DEFINITION_OF_DONE.md#isolated-database-checks): `personnel_sensitive_artifact_reads.sql`, `personnel_counseling_file_scope.sql`, `personnel_artifact_rls_group_scope.sql`, `personnel_leader_note_traversal.sql` and `counseling_deletion_approval_atomic.sql`. These establish RLS, Storage paths, traversal and request/record boundaries separately from native UI and authenticated HTTP. Never aim them at a remote or existing local database.
- Restore every armed control, compare retained rows/files, run final doctor, clean only recorded helper-created rows/files and dispose the owned worker. Preserve failures, unrun retention/provider boundaries and exact artifacts when packaging durable evidence; preparation alone does not complete the owning issue.
