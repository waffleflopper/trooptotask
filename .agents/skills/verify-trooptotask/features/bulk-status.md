# Bulk status changes

A Calendar operator applies a status to selected people, imports reviewed rows, or removes matching entries with clear partial results and whole-entry warnings.

## Sub-features

- `bulk-add`: choose a status chip, inclusive dates and note, then select allowed People. Each row shows that person's existing entries for the chosen dates; a person already on the same status is disabled, a person on another status stays selectable and is counted. Save from the summary bar and reread only the saved rows.
- `bulk-import-review`: invalid dates, missing or ambiguous names are explained before saving; valid selected rows show a completed result until Done.
- `bulk-remove`: review a partial overlap, back out without change, or confirm deletion of the whole saved entry; the success message reports how many entries the server actually deleted.
- `bulk-partial`: if the second of two chunks fails, the first 500 remain saved, one Person and the submitted draft remain ready for retry, and the result says 500 of 501. The 500 saved people now show as `Already on …` and are disabled, so only the failed Person stays selected. Retry saves only that Person.

## How to get to it (user POV)

From `Calendar`, choose `Bulk Status`. The page opens with the `Bulk status` heading (eyebrow `Calendar · Bulk status`) and the `Add`, `Remove` and `Import CSV` views, which keep the choice in the `tab` query; `Back to calendar` leaves. On a narrow viewport the `Back to calendar` link moves into the toolbar's overflow menu. Add saves from its summary bar (`Add to N people`) with no confirmation step; Remove leads to `Review Matching Entries`, and Import to `Parse`/`Next`. The operator needs Calendar operate access and a scope that includes the selected people; the Import tab accepts pasted CSV. The seeded Able/Baker/Unassigned records belong to A, while Foreign belongs to B.

## Gotchas

- An import row whose start or end date is an impossible calendar day, such as `2026-02-30`, is flagged during review and not sent; valid rows in the same paste still import. See [Invalid input](invalid-input.md).
- Add/Remove/Import are distinct user paths. A direct authenticated batch request can check server effects but does not demonstrate the tab's review and feedback.
- An import preview error is not enough to prove no save; compare rows before and after using the attempted unique note. Keep the completed import result visible for evidence before clicking Done.
- The partial-chunk control must see two actual batch calls. Check `network state`; if the second call never occurred, record the path as unreachable or failed rather than crediting a generic error toast. The 501 temporary People can make the roster slow; clean only the helper-owned IDs after proof.
