## Execution rules

- Retained contracts R1–R8, inventory M01–M17 and defects F01–F11 refer to [BASELINE.md](BASELINE.md). Its `UC/`, `AD/`, `EN/`, `ORG/` path abbreviations apply here. “Tests” means adjacent behavioral tests for owned files, not unrelated suites.
- At every driver invocation, reconcile the checkpoint, active parent/child and actual GitHub PR/merge state under the [issue-aware operating rules](../agents/operating-rules.md#stabilization-tasks) and [workflow #1275](https://github.com/waffleflopper/trooptotask/issues/1275). Finish the authorized fixed issue through bounded steps; stop at each PR/publication/merge boundary. Intermediate PRs reference the child; only final full acceptance closes it. Dependent work waits for verified integrated prerequisites. Checkboxes mean implemented/verified, not merged.
- Every task owns one behavior or boundary. Resolve imports and callers in the same task; delete the obsolete implementation, do not leave compatibility facades. A feature inventory row is not permission to rewrite its whole workflow at once.
- **G** = the complete [required command sequence](../architecture/DEFINITION_OF_DONE.md#required-commands): formatting write/check, lint, governance, Svelte/types, retained tests and production build after final implementation changes. Use that contract for focused checks, documentation checks, computer-use flows and reproducible performance evidence. Failures and unavailable evidence remain explicit, never a passing gate; no bypasses, allowlists, skipped assertions, inflated budgets or hidden scan paths.
- **DB** = the [isolated database contract](../architecture/DEFINITION_OF_DONE.md#isolated-database-checks): synthetic fixtures, fresh replay/upgrade, positive/negative RLS and retained identities in a disposable project with distinct ports outside existing 543xx/553xx/563xx stacks. Read lifecycle/seed configuration first; never load the legacy seed, access remote DBs or modify existing local data. Existing authorization covering isolated verification is sufficient; clean up only resources created for it.
- A task closes only when its stated verification and measurable acceptance pass, owned obsolete consumers are gone, and TODO/EVIDENCE record concise current acceptance with exact committed references. Consolidate accepted attempts and compact completed phases; preserve failures, unresolved findings, final verification and release obligations rather than an append-only diary. Historical migration text is not an active object; live compatibility code is not historical documentation. Keep append-only migration provenance; no wholesale port from v2.
- Before each child executes, refine its affected behavior/contract coverage and complete outcome with exact owners, callers, prerequisites, deletions and acceptance. Extend affected feature recipes/controls and exercise the unchanged behavior before refactoring; repeat affected live journeys afterward and independently review requirement completeness and results alongside applicable lower-level checks. Local steps do not impose one-leaf stops. See the installed [verification workflow](../../.agents/skills/verify-trooptotask/SKILL.md). Phase 10 still requires consumer-by-consumer expansion; apply the same detail to distant phases 11–15 when prerequisites expose final paths. Do not mark a phase complete after one example.
- Data uncertainty blocks only the affected deletion. Preserve stored Calendar facts and referenced types by default; proceed with runtime removal and safe schema planning. Explicit phase activation authorizes the [bounded stabilization tracker writes](../agents/issue-tracker.md). Git commit/push/PR creation, merge, release, deployment, remote SQL/provider administration, financial actions, live-data access and existing-local-database reset still require their separate authorization; root protections remain unchanged.
